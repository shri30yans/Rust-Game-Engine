# engine-scene: levels and tuning as files, and a default presenter (developer experience, build step 3)

Goal: make a game cheaper to write and to edit. Today each game hand-writes its scene in Rust, spawns bodies and entities by hand, and writes its own draw loop (the sandbox is about 1000 lines). After this brief: (1) a level is a validated data file (`.ron`) listing shapes, materials, spawn points, waypoints and named markers; (2) one call spawns the physics bodies, colliders, transforms and `Visual` components from it; (3) a generic `ScenePresenter` draws every entity with a `Visual` (blended between ticks) so a game only supplies camera, HUD and input; (4) in development builds the level and a game's tuning file reload while the game runs, so you edit a number or move a wall and see it within a second without recompiling. Release and Android builds embed the same files at compile time with `include_str!`; there is ONE loader and no fallback path. Done means: the sandbox's scene is expressed as a data file and loaded through this path with its existing scripted tests still passing unchanged, the new crate is unit and property tested, hot reload is tested, and all gates pass.

Read first: `AGENTS.md`, `docs/ARCHITECTURE.md` §0-1, `docs/README.md` §7 D24, D36, D37, `docs/CONTENT.md`, `games/sandbox/game/src/{scene,sim,present,lib}.rs`, `engine/app/src/{client,extract}.rs`, `engine/render/src/{mesh,gfx/config}.rs`, `engine/render/src/hot_reload.rs` (the existing file-watch pattern for shaders: reuse its mechanism, do not write a second watcher), `engine/physics/src/{world,body,collider}.rs`.

## New crate `engine/scene` (package `engine-scene`, layer 3; depends on `engine-core`, `engine-world`, `engine-physics`, `glam`, `serde`, `ron`, `thiserror`; NO render dependency; add to workspace and `layers.json`)
**Data model (`src/model.rs`), all `serde` with validated `TryFrom` raw types so an invalid file cannot become a value:**
- `Level { version: u32, name, gravity, shapes: Vec<ShapeDef>, spawns: Vec<Marker>, waypoints: Vec<Marker>, markers: Vec<Marker> }`.
- `ShapeDef { name: Option<String>, kind: Cuboid{half} | Sphere{radius} | Capsule{half_height, radius} | Ramp{half, tilt_deg} , translation: [f32;3], rotation_deg: [f32;3] (Y,X,Z order documented), body: Static | Dynamic{mass_kg} | Kinematic, look: Look }`.
- `Look { material: MaterialKind (enum: Floor, Wall, Concrete, Brick, Metal, Wood, Crate, Glass, Emissive, Custom{colour_hex, roughness, metallic}), tint: Option<[f32;3]> }`. Material kinds are names the renderer maps; the scene crate only stores them.
- `Marker { name, translation, yaw_deg }` (player spawn, bot spawn, waypoint, pickup; the `kind` is a free string the game interprets, listed in the game's docs).
Validation: finite numbers, positive extents and masses, unique names, `version` equals the supported version (an unsupported version is a typed error, no best-effort parse), at most N shapes (const, documented). Errors are `SceneError` with the file name, the shape index or name and the reason (use `ron`'s span for parse errors; keep the source error).

**Spawning (`src/spawn.rs`):** `pub fn spawn_level(world: &mut World, physics: &mut PhysicsWorld, level: &Level) -> Result<Spawned, SceneError>` creates, per shape, one entity with `Transform` (scale = full size), `Visual { mesh: MeshKind, look: Look }` (a registered component, `Replication::Replicated` per D36 conventions) and a physics body + collider; returns `Spawned { bodies: Vec<(NetId, BodyId)>, markers: Markers }` where `Markers` gives typed lookup by kind and name, in file order (no hash map; ordering is deterministic). `Visual` and `MeshKind` (Box, Sphere, Capsule, Ramp unit meshes the renderer scales) live in this crate.

**Loading and reload (`src/source.rs`):** `pub enum LevelSource { Embedded(&'static str), File(PathBuf) }`, `LevelSource::load() -> Result<Level, SceneError>`. A game chooses at compile time with one macro-free pattern: `cfg!(debug_assertions)` picks `File` pointing at the crate's own `levels/x.ron` (path from `env!("CARGO_MANIFEST_DIR")`), otherwise `Embedded(include_str!(...))`; Android always embeds. A `LevelWatcher` (reuse the shader hot reload's polling mechanism, behind the same small trait if one exists, else extract the shared piece rather than copying it) reports "changed" and the app then calls `reload`: despawn every entity and physics body the previous `Spawned` created, spawn the new level, re-place the player at the first player spawn marker only if the player's body is now inside geometry. A level that fails to parse or validate keeps the OLD level running and the error is shown in the HUD/log: this is the same contract as shader hot reload and is the one allowed non-crash behaviour, and only in the reload path, never at startup.
**Tunables:** `pub struct Tunables<T>`: `T: DeserializeOwned + Validate`, loaded from a `.ron` through the same `LevelSource`-style Embedded/File choice and the same watcher; `Validate` is a small trait (`fn validate(&self) -> Result<(), String>`). A game's `data.rs` structs (rifle, controller, bot, respawn) implement it, so numbers are editable live.

## `engine/app` additions
- `ScenePresenter`: a reusable helper (not a `Presenter` impl a game must accept) that does the common draw: for every entity in the frame with a `Visual`, build an `Instance` from the blended transform and the `MeshKind`/`Look` mapping (`MaterialKind` to the render crate's `Mat`/`Pattern`, one `match`, tested), draw it. Games compose it from their own `Presenter::draw` and add bots, HUD and effects around it. The `Extractor` must carry `Visual` (extend `RenderFrame` additively, capacity pre-sized as today, no allocation per frame: the existing `no_alloc` test is extended to cover a frame with visuals and must still pass).
- A debug overlay helper `ErrorBanner` that draws the last reload/validation error text at the top of the screen with the `Ui` (used by the reload path).

## Port the sandbox
`games/sandbox/game/levels/sandbox.ron` holds today's scene (floor, walls, 0.25 m step, 20-degree ramp, crate stack, player spawn); `scene.rs` shrinks to loading it and the sandbox's remaining specifics; `present.rs` uses `ScenePresenter` for the scene draw. The existing sandbox tests (`determinism.rs`, `movement.rs`, golden hashes) must pass WITHOUT editing their expected values; if the physics step order changes a hash legitimately, explain exactly why in the report instead of regenerating silently. Net line count of the sandbox crate must go down; report before and after.

## Tests
Unit: every validation rule has a failing file test (inline RON strings): bad version, duplicate names, non-finite, zero extent, unknown material, unknown field (use `deny_unknown_fields`), over the shape limit; a round-trip `to_string`/parse of a generated level (proptest generating valid levels); the spawn count and ordering; `Markers` lookup order. Integration (`tests/reload.rs`, no sleeps: drive the watcher with an injected clock/mtime source, or poll deterministically): load level A, spawn, replace the file contents with level B (written under `std::env::temp_dir()` in a unique per-process folder), the watcher reports change, `reload` leaves exactly B's shapes and no leftover bodies (assert `body_count` and `world.len()`), a broken file C keeps B running and surfaces the error, then a fixed file D loads. Tunables: edit-and-reload test with a validated struct, invalid value rejected and old value kept.
