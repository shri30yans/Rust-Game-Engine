# world-pipeline: build a world in Blender, play it in the engine (H-gap 3, D15, D41, D53)

Goal: a designer builds an arena in Blender from a modular kit and prefabs, presses export, and plays it. Done means:
1. `tools/blender/export.py` checks the rules in `docs/CONTENT.md` §2 and exports the scene with its tags.
2. The cooker turns it into one `Level` file that references cooked meshes, collision and prefabs by stable asset id: geometry, colliders, spawns, zones, objectives, probes, sound zones, movers, layouts and cues.
3. Prefabs are data files the game extends with its own components.
4. A running dev build picks up a re-export within seconds and updates only what changed.
5. A sample arena generated by a script proves the whole path in the sandbox and IMAGINE, and the four gates pass.

Unreal's model, which we follow: the level holds actors that are instances of reusable classes or Blueprints (here: prefabs) placed with per-instance overrides; assets are referenced by a stable path or id that survives a rename (soft object references plus redirectors); a re-imported asset updates every placed instance.

## Design

**1. Stable asset ids.**
- `export.py` gives every exported object, and every source file, an `asset_id` custom property: a random 64-bit id, written once and never changed.
- The cooker writes `cooked/index.ron`, mapping `AssetId` → cooked file and node, with the content hash.
- A runtime reference is an `AssetId`, never a path. Renaming or moving a file in Blender keeps every reference working.
- Two objects with the same id is a cook error (it happens when objects are duplicated in Blender); `export.py` re-ids the copy and warns.

Blender layout authoring convention:
- Scene custom property `layouts` is an ordered comma-separated lower_snake_case list; the first is the default.
- Each `role=mover` has exactly one child empty named `<mover>@<layout>` per layout. Its world transform is that layout's mover pose. Missing or extra pose children are exporter and cooker errors naming the mover.
- A switchable object has `switch=<name>` and one `layout_<layout>` property per layout, with value `on` or `off`. Missing or extra state fields are errors naming the object and field.
- A cue empty is named `CUE_<name>` and has `layout=<target>` and positive `duration_s`. The Director name omits the prefix. Firing it moves only movers and switches whose values differ from the current and target layouts, over that duration.
- The cooker emits each layout as `name -> (mover AssetId -> world pose, switch AssetId -> on/off)` and each cue as `name -> (target layout, duration_s)`.

**2. `export.py`**, as specified in ASSETS §2.4:
- Rule checks, each reported as object name plus what to fix: metres, applied scale and rotation, origins, `_COL` and `_LOD` naming, known tag values, sockets.
- Exports GLB with extras.
- Command line and an add-on panel button.
- Runs headless in a test: export a generated `.blend` and assert the GLB's tags.

**3. One level format.**
- `engine-scene`'s `Level` gains:
  - `instances` (asset id, node, transform, optional material override): static meshes drawn as retained primitives;
  - `colliders` (cooked collision set by asset id, or the existing greybox shapes);
  - `prefabs` (prefab id, transform, overrides);
  - `volumes` (zone, trigger, probe, sound, each a box with tags);
  - `layouts` (name → the rest pose of every mover and the state of every switchable thing, PLAN §3.3);
  - `cues` (Director names → the objects they act on).
- Hand-written RON greybox levels remain valid: they are the same format with only shapes and markers.
- The cooker writes `<arena>.level.ron` from the Blender scene: static nodes become instances plus a merged collision set, empties become markers and volumes by prefix, tagged nodes become prefab placements or movers.
- There is one runtime path: a `Level` is a `Level`, whoever wrote it.

**4. Prefabs.**
- `content/prefabs/<name>.prefab.ron`: an asset id for the model, a collision choice, a surface, sounds and effects by id, and a list of **component blocks**.
- A component block is a named, typed record such as `door { open_s: 0.6 }`, `health { hp: 200 }` or `explosive { radius_m: 6 }`. The game registers the blocks it understands: name → serde type → spawn function, through a `PrefabRegistry` in `engine-scene`.
- The engine knows no game's blocks (D24). An unknown block, or one that fails its type, is a load error naming the prefab file and the field.
- A placement may override block fields; overrides are validated against the same type.

**5. Live update** (dev builds only; D41's rules stand: validate first, apply at a tick boundary, keep the last good version):
- `cook --watch <dir>` re-cooks changed GLBs and prefab files incrementally (content-hash cache) and rewrites the level and the index.
- The running game's `LiveScene` diffs the new `Level` against the running one **by stable id**: moved instances change transform, new ones spawn, removed ones despawn, and a changed mesh or collision swaps through `AssetStore` hot reload.
- Entities that gameplay has changed (a moved crate, a destroyed wall) are left alone until the next match or travel, like play-in-editor discarding play changes.
- Test the diff with three versions of a level: move, add and remove, and change a prefab block.

**6. The sample arena.**
- `tools/blender/make_sample_arena.py` (headless Blender, like `make_pistol.py`) generates:
  - a small modular kit: wall 4 m, wall with door, floor 4×4, stairs, ramp, pillar, railing, on one trim-sheet material with base colour, normal and ORM textures (procedurally generated images are fine);
  - prefabs: crate (prop), explosive barrel, sliding door (mover with an `open` and a `closed` layout), turret placeholder;
  - an arena about 40×40 m with two floors, spawns for two teams, two zones, one objective, two probe volumes, one sound zone, and two layouts (`open`, `lockdown`) with a cue that switches them.
- It runs the export and the cook, and is committed with its outputs (Git LFS for binaries, D16).
- The sandbox loads it as a test scene. IMAGINE can select it as an arena in its data, and the existing arena stays the default until art is ready.

## Tests
- `export.py`: every rule violation is reported; ids are stable across two exports; duplicates are re-id'd.
- Cooker: the sample arena cooks byte-identically twice; the level validates; every reference resolves through the index; a missing reference is a cook error naming the object.
- Prefabs:
  - the registry rejects unknown blocks and bad types with file and field;
  - overrides apply;
  - the same prefab placed 100 times shares one mesh and one collision shape.
- Live diff: the three-version test above. No entity id changes for unmoved objects. Running on a level with 500 instances allocates only when something is added.
- A headless play test: load the sample arena in IMAGINE with bots for 600 ticks, then switch layout through its cue. No errors, a stable state hash across two runs, and every mover reaches its layout pose.
- A golden image of the sample arena in the sandbox.
